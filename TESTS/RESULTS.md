# Test results

Generated by `linux/test/suite.py --matrix` from `BASELINE/` (QEMU, TCG,
64 MB), branch main (8.x, maintenance).  Columns: profile and DOS.  `SKIP`:
the profile lacks the service (see `needs=` in the lists).  `qemm` is
QEMM 97 with QDPMI (local reference image, not distributed).

## State of 386MAX 8.x

Own tests (those of `MAX.LST`):  all PASS on MS-DOS 6.22 and 7.1,
EDR-DOS, SvarDOS and FreeDOS.  The tests of 9.x features are in the tree
but not listed for 8.x.

HDPMI regression tests (suite `hx`):  see the `max` column.

Bug fixes from 9.x in 8.x:  DPMI faults terminate the client with a short
report (as CWSDPMI/HDPMI) instead of stopping the machine; the page
tables are no longer writable by clients (STKFLT crashed); EMS mapping
contexts are checked (EMSFUNC hung); INT 31h 0300h leaves the CS:IP of the
caller's structure alone; INT 21h 440Dh/440Ch subfunctions without a
translation are passed through (hang on EDR-DOS and MS-DOS 7.1, DOS memory
corrupted on FreeDOS); nested DPMI clients no longer run the ring 0 stack
into the tables below it (HX's NEWCL); an XMS allocate from a DPMI client
takes the pages back from the virtual memory pool (XMSMAP, VSBHDA "DMA
buffer init failed"); starting a nested client no longer leaves a
selector for its PSP in the parent's LDT; a client that set an INT 33h
000Ch handler and exits without a mouse reset no longer leaves the
driver calling its freed memory; 386LOAD.COM uses the kernel's UMB chain
on FreeDOS with DOS=UMB.
